# AI-слой

**Принцип:** LLM ничего не обнаруживает. Находки дают только собственные анализаторы, LLM лишь объясняет готовые
результаты. Любой её ответ сначала проходит валидатор и только потом сохраняется или показывается. Без LLM платформа
работает полностью: AI-ноды переключаются на детерминированный fallback и явно об этом сообщают.

## Где используется LLM

| Функция | Модуль | Что получает LLM | Что проверяется |
| --- | --- | --- | --- |
| AI-отчёт (`ai.report`) | `app/ai/report_service.py`, `prompts.py` | маскированные находки + ±3 строки контекста | схема, `finding_id`, файл/строки, `fix.before` совпадает с файлом, CVE/GHSA, безопасная версия |
| Генерация сценария из текста, чат-правки | `app/ai/workflow_gen.py` | каталог нод из реестра (типы, порты, схемы) | тот же валидатор графа, что и для ручных сценариев, до 3 попыток исправления; секреты литералами не принимаются |
| AI-план спринта | `app/scoring/sprint_plan.py` | только `finding_id`, класс, severity, новизна, трудоёмкость, ожидаемый прирост | неизвестные/дубли id удаляются, `projected_score` пересчитывается детерминированно |
| AutoFix | `app/autofix/service.py`, `validator.py` | маскированный фрагмент файла с номерами строк | 7 шагов: схема, место, `old_snippet`, отсутствие секретов, применение к копии, синтаксис (tree-sitter), самопроверка всеми анализаторами |

## Провайдеры

Рабочие пространства по умолчанию наследуют выбор платформы. Администратор может сохранить собственный выбор в «Настройки → AI».

| Провайдер | Подключение | Модель |
| --- | --- | --- |
| NVIDIA Nemotron (`nvidia`, по умолчанию) | `https://integrate.api.nvidia.com/v1`, ключ NVIDIA | `nvidia/nemotron-3.5-lightning-30b-a3b` |
| Ollama (`ollama`) | `http://ollama:11434` в Compose, `http://localhost:11434` на хосте | Установленная модель, например `qwen2.5:3b` |

### Настройки платформы

Для Compose задайте параметры в корневом `.env`, для запуска Python на хосте — в `backend/.env`.
Для Nemotron укажите `NVIDIA_API_KEY`. Для Ollama задайте `LLM_PROVIDER=ollama`, `OLLAMA_URL` и `OLLAMA_MODEL`.
Переменная `LLM_ENABLED=false` отключает провайдер платформы. После изменения окружения перезапустите backend и воркер.

```bash
docker compose --profile ollama up -d
docker compose exec ollama ollama pull qwen2.5:3b
```

### Проверка соединения и отчёта

Кнопка проверки соединения и CLI принимают JSON-объект с логическим `"ok": true`. Диагностика показывает
результат для каждого настроенного прокси и прямого соединения. Для проверки окружения выполните
`cd backend && python -m app.ai.check_llm`. Переключение рабочего пространства проверяйте в интерфейсе.
Ключи и пароли прокси рабочего пространства хранятся в зашифрованном хранилище.

Нода `analysis.ai_coverage` принимает выход `ai.report`. В результате `total` учитывает все находки,
включая находки сверх лимита модели. `explained_by_ai` показывает число принятых валидатором объяснений,
а `deterministic` — число объяснений по правилам платформы. Для ветки ручной проверки укажите в IF/ELSE
условие `data.needs_review == true`. При пустом наборе оба счётчика равны нулю и условие ложно.

## Что уходит в LLM

- Только маскированные данные. Значения секретов заменяются на `ab…(len=N)`, в сниппетах маскируется каждый
  литерал-фрагмент. Ключи провайдеров, уведомлений и SCM регистрируются в маскировщике при расшифровке.
- Минимальный контекст: находка (класс, правило, путь, строки, severity, CWE, advisory) и несколько строк кода. Весь
  репозиторий не отправляется.
- AI-план спринта получает только числа и id, без путей, сниппетов и авторов. Тест сверяет точный набор ключей.

## Валидатор отчёта (`app/ai/validator.py`)

1. JSON и схема `REPORT_SCHEMA`. При ошибке — одна попытка исправления.
2. Каждый `finding_id` существует, дубли запрещены. Неизвестные id отбрасываются и учитываются в метрике.
3. `fix.path` и строки относятся к этой находке (или её `alternateLocations`), `fix.before` дословно (с
   нормализацией пробелов) совпадает с маскированным текстом файла. Ссылки вида `file:line` в тексте должны
   существовать.
4. CVE/GHSA допустимы только из пересечения «база уязвимостей ∩ находки запуска». Остальные вырезаются, ставится флаг
   `hallucinated_ids`.
5. `safe_version` у SCA должна входить в `fixedVersions` advisory, иначе её исправляют на ближайшую.
6. Каждое решение (принято / исправлено / отброшено) пишется в журнал. UI показывает индикатор доверия и метрики.

Находки, для которых LLM не дала валидного объяснения, заполняются детерминированным текстом
(`app/ai/deterministic.py`). Их число попадает в метрику `filled_deterministic` журнала валидатора.

## Без LLM

- `ai.report` — детерминированный отчёт (влияние, шаги исправления, безопасная версия). В логе ноды:
  «AI недоступен, сформирован отчёт без AI: …». Fallback можно отключить параметром `fallback_to_deterministic`.
- AI-план спринта — жадный план с бюджетом 8 единиц трудоёмкости.
- AutoFix: SCA работает без LLM (детерминированное обновление версии). Для остальных правил — понятная ошибка
  `ai_not_configured`.
- Генерация сценария из текста недоступна, кнопка показывает причину.

## Проверка

AI-слой проверен контрактными тестами: локальные HTTP-серверы отвечают в форматах провайдеров, включая некорректные
ответы, галлюцинированные CVE, чужие `finding_id`, неверные строки, тайм-ауты и `429`. Тесты: `backend/tests/ai/`,
`tests/api/test_autofix_api.py`, `tests/api/test_score_api.py`. Живой прогон NVIDIA Nemotron на одной находке
описан в разделе 8 `docs/REPORT.md`.

## Оценка полезности рекомендаций

Команда прогоняет весь набор находок проекта через настроенную модель по тому же пути, что и нода `ai.report`.
Берутся только находки из официальной выгрузки, детерминированный fallback отключён. Ответ проходит валидатор, затем
каждое принятое объяснение проверяется по трём критериям:

| Критерий | Что считается полезным |
| --- | --- |
| Указано место | Объяснение называет конкретный файл; для SCA — файл объявления или артефакт |
| Есть шаги | Хотя бы один конкретный шаг исправления |
| Diff или версия | SECRET/SAST: валидатор принял diff исправления; SCA: безопасная версия совпадает с `fixedVersions` справочника |

Отдельно выводятся метрики валидатора: принято и отброшено пунктов, выдуманных CVE/GHSA, неверных ссылок на
файл:строку, принятых и отклонённых diff. Объяснения, которые платформа дописала сама, моделью не считаются.

```bash
cd backend
NVIDIA_API_KEY=… .venv/Scripts/python -m app.ai.eval_report                    # учебный проект организаторов
.venv/Scripts/python -m app.ai.eval_report --project <корень проекта> --json eval.json
```

Без настроенной модели команда завершается с кодом 2 и ничего не «оценивает». Код: `app/ai/eval_report.py`, тесты:
`tests/ai/test_eval_report.py`.
