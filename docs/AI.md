# AI-слой

**Принцип:** LLM ничего не обнаруживает. Находки дают только собственные анализаторы, LLM лишь объясняет готовые
результаты. Любой её ответ сначала проходит валидатор и только потом сохраняется или показывается. Без LLM платформа
работает полностью: AI-ноды переключаются на детерминированный fallback и явно об этом сообщают.

## Где используется LLM

| Функция | Модуль | Что получает LLM | Что проверяется |
| --- | --- | --- | --- |
| AI-отчёт (`ai.report`) | `app/ai/report_service.py`, `prompts.py` | маскированные находки + ±3 строки контекста | схема, `finding_id`, файл/строки, `fix.before` совпадает с файлом, CVE/GHSA, безопасная версия |
| Генерация сценария из текста, чат-правки | `app/ai/workflow_gen.py` | каталог нод из реестра (типы, порты, схемы) | тот же валидатор графа, что и для ручных сценариев, до 3 попыток исправления; секреты литералами не принимаются |
| AI-план спринта | `app/scoring/sprint_plan.py` | только `finding_id`, класс, severity, новизна, трудоёмкость, ожидаемый прирост | неизвестные/дубли id удаляются, `projected_score` пересчитывается детерминированно |
| AutoFix | `app/autofix/service.py`, `validator.py` | маскированный фрагмент файла с номерами строк | 7 шагов: схема, место, `old_snippet`, отсутствие секретов, применение к копии, синтаксис (tree-sitter), самопроверка всеми анализаторами |

## Провайдеры

Настройки → AI-провайдер (admin). Ключ хранится в зашифрованном хранилище. Все запросы идут через SSRF-фильтр.

| `provider` | Пример `base_url` | Комментарий |
| --- | --- | --- |
| `ollama` | `http://ollama:11434` (профиль `ollama`) или `http://localhost:11434` | Бесплатно, код не покидает машину. Модели: `qwen2.5:7b`, `llama3.1:8b`. |
| `openai_compat` | `https://openrouter.ai/api/v1` | У OpenRouter есть бесплатные модели с суффиксом `:free`. |
| `openai_compat` | `https://generativelanguage.googleapis.com/v1beta/openai` | Google Gemini, например `gemini-2.0-flash`. |
| `openai_compat` | `http://localhost:1234/v1` | LM Studio, vLLM, llama.cpp server (включите «разрешить локальный адрес»). |
| `openai_compat` | `https://api.openai.com/v1` | Любой OpenAI-совместимый API. |

С профилем `ollama`:

```bash
docker compose --profile ollama up -d
docker compose exec ollama ollama pull qwen2.5:7b
```

Затем укажите в настройках `ollama`, `http://ollama:11434`, `qwen2.5:7b` и нажмите «Проверить соединение».

**Режим JSON** (`json_mode`): `auto` пробует JSON Schema, затем `json_object`, затем инструкцию в промпте; можно
зафиксировать вручную. При сбое формата делается одна попытка исправления с текстом ошибки (`REPAIR`).
Сетевые ошибки и `429`/`5xx` повторяются с экспоненциальной задержкой.

**Новый провайдер** — класс-наследник `LLMProvider` с методами `chat()` и `list_models()` и декоратором
`@register_provider` в `app/ai/providers/`.

## Что уходит в LLM

- Только маскированные данные. Значения секретов заменяются на `ab…(len=N)`, в сниппетах маскируется каждый
  литерал-фрагмент. Ключи провайдеров, уведомлений и SCM регистрируются в маскировщике при расшифровке.
- Минимальный контекст: находка (класс, правило, путь, строки, severity, CWE, advisory) и несколько строк кода. Весь
  репозиторий не отправляется.
- AI-план спринта получает только числа и id, без путей, сниппетов и авторов. Тест сверяет точный набор ключей.

## Валидатор отчёта (`app/ai/validator.py`)

1. JSON и схема `REPORT_SCHEMA`. При ошибке — одна попытка исправления.
2. Каждый `finding_id` существует, дубли запрещены. Неизвестные id отбрасываются и учитываются в метрике.
3. `fix.path` и строки относятся к этой находке (или её `alternateLocations`), `fix.before` дословно (с
   нормализацией пробелов) совпадает с маскированным текстом файла. Ссылки вида `file:line` в тексте должны
   существовать.
4. CVE/GHSA допустимы только из пересечения «база уязвимостей ∩ находки запуска». Остальные вырезаются, ставится флаг
   `hallucinated_ids`.
5. `safe_version` у SCA должна входить в `fixedVersions` advisory, иначе её исправляют на ближайшую.
6. Каждое решение (принято / исправлено / отброшено) пишется в журнал. UI показывает индикатор доверия и метрики.

Находки, для которых LLM не дала валидного объяснения, заполняются детерминированным текстом
(`app/ai/deterministic.py`). Их число попадает в метрику `filled_deterministic` журнала валидатора.

## Без LLM

- `ai.report` — детерминированный отчёт (влияние, шаги исправления, безопасная версия). В логе ноды:
  «AI недоступен, сформирован отчёт без AI: …». Fallback можно отключить параметром `fallback_to_deterministic`.
- AI-план спринта — жадный план с бюджетом 8 единиц трудоёмкости.
- AutoFix: SCA работает без LLM (детерминированное обновление версии). Для остальных правил — понятная ошибка
  `ai_not_configured`.
- Генерация сценария из текста недоступна, кнопка показывает причину.

## Проверка

Реальной LLM в окружении разработки не было. AI-слой проверен контрактными тестами: локальные HTTP-серверы отвечают в
формате OpenAI/Ollama, включая некорректные ответы, галлюцинированные CVE, чужие `finding_id`, неверные строки,
тайм-ауты и `429`. Тесты: `backend/tests/ai/`, `tests/api/test_autofix_api.py`, `tests/api/test_score_api.py`.
