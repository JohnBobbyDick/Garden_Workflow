# План реализации AI Security Workflow

Источник требований: `Garden Центр-инвест.pdf` (главный), `prompt.md` (детальная постановка), `TZ.md` (чеклист). Рабочий чеклист исполнения — `todo.md`.

## Модули

| Модуль | Где | Назначение |
|---|---|---|
| Анализаторы | `backend/app/analyzers/{common,secrets,sca,sast,diff}` | Собственные SECRET/SCA/SAST, единая модель `Finding`, критичность, diff-классификация |
| Экспорт | `backend/app/export` | `submission.json` (формат организаторов + валидатор), Markdown, HTML |
| Движок | `backend/app/engine` | Граф, валидатор, исполнитель (asyncio, IF-skip, параллельность, таймауты, отмена), события, SSE, очередь в БД, планировщик |
| Ноды | `backend/app/nodes/**` | Плагины с автообнаружением: один файл = одна нода |
| Безопасность | `backend/app/core` | JWT, роли, AES-GCM, Masker, SSRF, repo-guard, аудит |
| AI | `backend/app/ai` | Провайдеры OpenAI-compatible/Ollama, промпты, схемы, валидатор достоверности, генерация/чат графа |
| CI/CD | `backend/app/ci`, `cli/aisw_ci.py` | API-токены, запуск из CI, YAML, вебхуки, статусы, gate |
| Фичи команды | `analyzers/diff`, `scoring`, `autofix` | Diff-aware, Security Score, AutoFix + PR |
| Frontend | `frontend/` | React 18 + TS + Vite + Tailwind + React Flow, Zustand, TanStack Query, i18n RU/EN, темы |

## Порядок

Фазы 0 → 1 → 2 → 3 → 4 → 5 → 6 → 6А → 7 → 8 (см. `todo.md`), каждая закрывается гейтом и коммитом.
Анализаторы идут первыми: от их точности на скрытой вариации зависит главная оценка.

## Ключевые технические решения

- Kotlin парсится `tree-sitter-kotlin` (проверено: Python 3.12, tree-sitter 0.26, грамматика 1.1). Грамматика разбивает простые шаблоны `$name` на отдельные `string_content`, поэтому строковые шаблоны декодируются собственным разборщиком по исходному тексту литерала.
- Общий IR поверх дерева: файлы → классы → функции → параметры с аннотациями; константы файла/класса/функции; поля конструктора с типами (основа графа вызовов).
- Секреты, SCA и SAST используют один разрешитель констант Kotlin (свёртка `+`, шаблонов, `format`, `joinToString`, `StringBuilder`, `Base64`, `reversed/trim/lowercase`).
- Собственный движок исполнения (решение команды; PDF разрешает Flowable/Temporal, мы их не используем).
- Очередь запусков — таблица БД (`FOR UPDATE SKIP LOCKED` на PostgreSQL; на SQLite — атомарный UPDATE с проверкой статуса).

## Риски

| Риск | Митигация |
|---|---|
| Оверфиттинг под учебный набор | Только общие правила; 3+ мутанта с другими приёмами и новыми контролями; grep-проверка на имена из набора |
| Нет реальной LLM в окружении (Ollama не установлен) | Контрактные тесты на локальном OpenAI-compatible сервере; детерминированный fallback с явной пометкой; честная запись в REPORT |
| Docker/PostgreSQL недоступны в момент тестов | Юнит-тесты на SQLite, отдельная цель `make test-pg`, прогон в Compose |
| Объём фронтенда | Генерация форм из JSON Schema; единая дизайн-система; e2e только на ключевой сценарий |
| Ложные срабатывания доп. SAST-правил | Правила 6–11 с пониженной уверенностью и порогом официальной выгрузки, проверка прогоном на учебном наборе |
